# Customer Sign-up - Test Cases

**Description:** Test scenarios for the customer sign-up feature of the demo app.
**Scope:** Field validation (pass and fail) on the `/customer-signup` screen (UI) and on `POST /api/customers` (API).
**Pairing:** UI and API cases are paired 1:1 by number (TCxx and APIxx cover the same field/rule, at different layers).

**Notes:**
- Notes outside the table are for people only: the extension sends only table rows to the LLM, so each case repeats the context it needs.
- Unless a case says otherwise, every other field is filled with valid data (e.g. a new unique email, a valid date of birth 18+ years ago, a valid ID number for the selected gender, phone "0912345678", terms accepted).
- API requests send the header `Authorization: Bearer <TEST_TOKEN>` (see `.env.example`) and a JSON body. Dates in the API body use the `dd/mm/yyyy` format.
- The app keeps its data in memory and starts with two seeded customers: email "existing.customer@example.com" with ID number "111111111111", and email "jane.doe@example.com" with citizen ID number "222222222222".
- Out of scope for this set: authorization (401), injection/security checks, accessibility and cross-device compatibility.
